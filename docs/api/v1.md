# Booknow API v1 — Mobile Application Reference

**Base URL**: `https://{root-domain}/agency/{tenant}/api/v1`  
**Auth**: Bearer token via `Authorization: Bearer {token}` header  
**Content-Type**: `application/json` (for POST/PUT/PATCH)

> **`{tenant}`** is your agency's path slug (e.g. `my-agency`). Every request must include it in the URL path: `https://booknow.ly/agency/my-agency/api/v1/...`

---

## Authentication

### 1. Login — Get Bearer Token

```
POST /agency/{tenant}/api/v1/auth/token
```

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `email` | string | ✅ | valid email |
| `password` | string | ✅ | — |
| `device_name` | string | ✅ | max 255 chars |

**Response** `200`:
```json
{
  "success": true,
  "message": "Token created successfully.",
  "data": {
    "token": "1|abcdef...",
    "user": {
      "id": 1,
      "name": "John Doe",
      "email": "john@example.com",
      "role": "agent",
      "is_active": true,
      "initials": "JD",
      "last_login_at": "2026-05-13T10:00:00.000Z"
    }
  }
}
```
- `403` — account deactivated
- `422` — invalid credentials

### 4. Revoke Token (Logout)

```
DELETE /agency/{tenant}/api/v1/auth/token
Authorization: Bearer {token}
```

**Response** `200`:
```json
{ "success": true, "message": "Token revoked.", "data": null }
```
- `400` — no Bearer token in request
- `404` — token not found or already revoked

```
Authorization: Bearer {token}
```

| Query | Type | Required | Description |
|-------|------|----------|-------------|
| `q` | string | no | IATA code (3 chars) or city/country name |

## eSIM usage & top-up

L2 pushes utilisation callbacks (1% / 50% / 80% / 100%). TAMS stores the latest snapshot on the order item; remaining quota is as fresh as the last webhook.

### Webhook (L2 → TAMS)

```
POST /agency/{tenant}/api/v1/webhooks/l2-esim
```

| Header | Value |
|--------|--------|
| `X-HMAC-Signature` | Base64(HMAC-SHA256(raw body, L2 API key)) |
| `Content-Type` | `application/json` |

Configure this URL in the L2 portal. Returns `200` quickly (including unknown ICCID / non-Utilisation alerts) so L2 does not retry forever. Invalid HMAC → `401`.

Useful body fields: `iccid`, `bundle.initialQuantity`, `bundle.remainingQuantity`, `bundle.unit`, `bundle.startTime` / `endTime`, `bundle.reference`, `bundle.name`.

### Top-up eSIM

```
POST /agency/{tenant}/api/v1/orders/{order_id}/esim-items/{item_id}/topup
Authorization: Bearer {token}
```

Requires `write`. Calls L2 `processOrders` with `item` + existing `iccid`, creates a linked top-up order, and debits the provider wallet (same finance path as purchase).

| Field | Type | Required |
|-------|------|----------|
| `package_id` | string | ✅ |

**Response** `201`: new top-up `order` + `esim` (`transaction_type: topup`, parent order/item ids) + `package`.

## Error Response Format

All errors follow a consistent shape:

```json
{
  "success": false,
  "message": "Human-readable error description",
  "errors": { "field": ["Validation message"] }
}
```

| HTTP Code | Meaning |
|-----------|---------|
| `200` | Success |
| `201` | Created (booking/issue confirmed) |
| `400` | Bad request |
| `401` | Unauthenticated (missing/invalid Bearer token) |
| `402` | Payment required (insufficient wallet balance) |
| `403` | Forbidden (account deactivated) |
| `404` | Not found |
| `410` | Gone (search/quote/booking session expired) |
| `422` | Validation error or provider failure |
| `502` | Bad gateway (airline/provider communication error) |

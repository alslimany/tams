Live / Production:
https://customer2.videcom.com/airlinename/vars/public/webservices/VRSXMLWebservice3.asmx?op=RunVRSCommand
 
You will be using the RunVRSCommand option - on the RunVRSCommand page, you will see a SOAP, HTML GET + POST samples - these are also attached at the end of this document.
 
Authentication
 
To use the booking and command functions, you need to use a supplied token – this is generated by Videcom from the sine code assigned by the airline and the end users IP address.  You will need to provide Videcom with the IP address / Sine Code / Password for the user who will be using the XML API, the sinecode and office will be allocated by the airline.
 
VRS XML Service Message
 
    <msg>
      <Token>string</Token>
      <Command>string</Command>
    </msg>
 
The identification token and a VRS command are sent into the API. The commands reach VRS in a new session where flight information may requested or bookings may be built up. The VRS sessions follow the airline AAA model so a booking may be called into the Agent Audit Area where it can be viewed or adjusted and then saved or ignored.
 
 
VRS XML Service - RunVRSCommand
 
You can run most vrs commands via the XML service - either on their own or linked together using ^. 
 
Many commands also have an xml response which may be requested by following up the command with ~x. To display a booking from the record locator (rloc) the entry would be:
 
*ABC123~x
 
The system will respond:
 
<PNR RLOC="AAT6Z8" SecureFlight="False" showFares="True" editFlights="True" editProducts="True">
  <Names>
    <PAX GrpNo="1" GrpPaxNo="1" PaxNo="1" Title="MR" FirstName="" Surname="TEST" PaxType="AD" Age="" />……..
 
 
To recall a booking, add some information and then save the booking requires several commands chained together using the ^ character. For example
 
 
*ABC123^5*Passenger Booked from Website^E*R~x
 
To break that down:
 
*ABC123 look up booking reference ABC123, this booking will now be in the Agent Audit Area session
 
 5*Passenger Booked from Website 5* is the action code which is followed by some text
 
E*R~x save the booking(End Transaction) display the current booking in xml format
 
 
When the API processes the commands any error occurring will suspend the execution and return the error response through the API in plain text.
 
Tip: When building and working with PNR’s, always end the transactions with *R~x so you will receive a common xml structure in response to those commands. It’s then simple to distinguish an error from a set of command s that completed normally. Depending on the interface the error may be displayed to the user or logged.
 
 
 
Price and Availability
 
 
Many API users need to obtain flight availability and pricing, this may be selected as a single one way flight or repeatedly with indicator that the flight is a return or multileg
 
 
The following entries return both availability with the fares in one entry:
 
Entry for a one-way itinerary:
A20NOVLOSABV[SalesCity=LOS,VARS=True,ClassBands=True,StartCity=LOS,SingleSeg=s,FGNoAv=True,qtyseats=1]
 
The attribute SingleSeg=s lets the system know this is a single flight.
 
 
Entry for a return itinerary:
A20NOVLOSABV [SalesCity=LOS,VARS=True,ClassBands=True,StartCity=LOS,SingleSeg=r,FGNoAv=True,qtyseats=1]
A24NOVABVLOS[SalesCity=ABV,VARS=True,ClassBands=True,StartCity=LOS,SingleSeg=r,FGNoAv=True,qtyseats=1]
 
SingleSeg=r indicates the flights are part of a multileg itinerary which may have different fares compared with single flights.

Price a Booking
 
Once the flight, date and class are known, a complete price can be obtained on a temporary basis without blocking space or creating a booking.
 
For example to get a specific price for a party of 2 adults, 1 child + 1 infant
 
i^-4Pax/A#/B#/C#.CH10/D#.IN06^0VL2100Y20NOVLOSABVQQ3^0VL2101Y24NOVABVLOSQQ3^FG^FS1^*r~x
 
Breaking that down:
 
I makes sure the process starts in a fresh empty session
-4Pax/A#/B#/C#.CH10/D#.IN06 add 4 PAX to the booking with last name Pax, the last PAX was an infant
0VL2100Y20NOVLOSABVQQ3 book flight VL2100 in class Y on the 20Nov from LOS to ABV using the QQ booking code which does not hold space for 3 PAX, not 4 as the infant is a lap child.
FG fare quote 
FS1 store the fare
*r~x display the booking in xml format
